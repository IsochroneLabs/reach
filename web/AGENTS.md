# web/AGENTS.md

Folder rules for the student web app. The root `AGENTS.md` applies; this file adds what is
specific to `web/`.

**Status (S2.2–S2.6, Nov 2026):** the student app with the modes *Find* and *Check* on top of a
typed API client. Until the API of S1.10 is deployed it runs in **fixture mode** on sample data
(`src/api/fixtures/`), labelled "Sample data" in the header. Screens, state and texts:
`docs/app_screens.md`.

## Layout

| Path | Content |
|---|---|
| `src/config.ts` | Build-time config: `BUILD_SHA`, `API_BASE`, `USE_FIXTURES`, `BASEMAP_STYLE` |
| `src/settings.ts` | Frontend-only settings (debounce, cache size, nearby radius, max places) |
| `src/api/` | `types.ts` (S1.4 shapes + PROPOSED fields, notes N17), `client.ts` (HTTP or fixtures) |
| `src/api/fixtures/` | Sample data `tuebingen.json` (generated by `scripts/make-fixtures.ts`) and `transport.ts`, which answers the API in the browser and in Playwright |
| `src/geo/laea.ts` | EPSG:3035 ↔ 4326 for cell ids (drawing and pins only) |
| `src/state/` | Student profile, places, URL hash, `localStorage` wrapper, store |
| `src/remote/` | Reference data and the fit request flow (debounce, abort, cache) |
| `src/i18n/` | `en.ts` (primary), `de.ts` (typed against `en.ts`), provider |
| `src/components/` | Header, profile panel, map, Find and Check results, bottom sheet, dialogs |
| `src/health.ts` | `GET /api/health` client (shown in the "About these numbers" dialog) |
| `scripts/make-fixtures.ts` | Regenerates the sample data (`npm run fixtures`) |
| `tests/` | Playwright tests (`smoke.spec.ts` also runs against deployed sites, `app.spec.ts`) |
| `src/**/*.test.ts` | Unit tests for pure modules (`npm run test:unit`, `node --test`) |
| `playwright.config.ts` | Local runs build + `vite preview` in fixture mode; `BASE_URL` runs the same tests against a deployed site |
| `wrangler.jsonc` | Cloudflare Worker `reach` with static assets from `dist/` (docs/deployment.md); unknown paths such as `/check` serve the app |
| `.nvmrc` | Node major version for CI and local development |

## Rules

- **Static build only.** No server-side code, no Worker script, no Cloudflare bindings. Data comes
  from the API; nothing is fetched from public data APIs (root rule 8).
- **Build-time config** comes from `VITE_*` variables, never hard-coded URLs:
  `VITE_BUILD_SHA` (set by CI to the commit SHA; `dev` locally; also in
  `<meta name="build-sha">`, which the deploy smoke test checks) and `VITE_API_BASE` (public API
  base URL without trailing slash; empty = no backend yet; `npm run dev` defaults to `/api`, which
  Vite proxies to `127.0.0.1:${API_PORT:-8000}`), `VITE_API_FIXTURES` (`1` = sample data in
  the browser; also on when `VITE_API_BASE` is empty) and `VITE_BASEMAP_STYLE` (basemap style on
  our own origin, D5; empty = plain background). New variables go into `src/config.ts`,
  `src/vite-env.d.ts`, this list and `.env.example`.
- **Privacy (root rule 9):** the student profile lives in the URL and `localStorage` only; no
  cookies, tracking, analytics or third-party scripts and fonts.
- **Every number on screen is explainable** (docs/product.md): show data date, trip window, mode
  and source next to it; label missing or uncertain values, never hide them (the placeholder shows
  "unreachable" when the API fails).
- **Mobile first, German and English,** accessible contrast; Playwright runs a desktop and a mobile
  project.
- **Look and feel follow [`docs/design.md`](../docs/design.md)** (direction *Atelier*, architecture
  O27): colour, type and spacing only from its tokens; rules R1–R10 (no shadows, gradients, rounded
  corners, emoji or icon packages, no accent colour). A PR that breaks a rule says why.
- **Deploys only through the workflows** (`ci.yml` previews, `deploy.yml` production). Never run
  `wrangler deploy` or `wrangler preview` by hand.

## Tests

- Playwright tests never call a real API: the local build runs in fixture mode, and `page.route`
  answers `/api/health`. Fixtures follow the shapes of `docs/data_contract.md`; fields the API
  does not have yet are marked PROPOSED in `src/api/types.ts` and listed in notes N17.
- Sample data is generated, never edited by hand: change `scripts/make-fixtures.ts`, run
  `npm run fixtures`, keep `tuebingen.json` < 1 MB.
- Every visible string is a key in `src/i18n/en.ts` with a German twin in `de.ts`.
- Tests that only make sense locally skip when `BASE_URL` is set; everything else also runs as the
  deploy smoke test against the live site (`EXPECTED_SHA` = deployed commit).

## Commands (from `web/`)

| Task | Command |
|---|---|
| Install | `npm ci` |
| Dev server | `VITE_API_FIXTURES=1 npm run dev` (sample data) · `npm run dev` (live API from `make up`) |
| Lint, type check + build | `npm run lint && npm run build` |
| Unit tests | `npm run test:unit` (Node ≥ 22.18, no extra packages) |
| Smoke and app tests | `npx playwright install chromium` once, then `npm run test:e2e` |
| Sample data | `npm run fixtures` |

Versions are pinned in `package.json` and `package-lock.json`; adding or upgrading a package needs
a yes (root `AGENTS.md`).
