## 1. Project Overview & Motivation

The **15-Minute City** is an urban planning framework where residents can access all essential daily services (food, education, healthcare, green spaces, transit) within a 15-minute walk or bicycle ride from their doorstep[cite: 7]. 

This project aims to build an end-to-end, automated data pipeline and interactive web application that:
1. Evaluates neighborhood-level compliance with 15-minute accessibility thresholds[cite: 7].
2. Identifies infrastructure bottlenecks and underserved areas[cite: 7].
3. Recommends optimal locations for new amenities using population-weighted optimization heuristics[cite: 7].

---

## 2. Core Functional Models

### Model 1: Micro-Level "Pin-Drop" Inspector
* **Function:** A user places a pin anywhere on the city map.
* **Outputs:**
  * Live calculated travel times (walk/bicycle) to all essential amenity categories.
  * Identification of the **restraining/bottleneck amenity** (the one exceeding or closest to exceeding 15 minutes).
  * Visualization of the exact routing path to the bottleneck or nearest facilities.
  * Compliance verdict (conforms vs. does not conform to 15-minute standards).

### Model 2: Citywide Accessibility Heatmap (H3 Tessellation)
* **Function:** Macro-level spatial assessment of the entire municipality.
* **Mechanism:** 
  * The city boundary is partitioned into an **Uber H3 hexagonal grid** (evaluating Resolution 9 vs. Resolution 10).
  * Centroids serve as origins; routing matrices compute shortest travel times to all amenity categories.
  * Cells are colored according to their bottleneck travel time (e.g., green <= 15 min, yellow <= 20 min, red > 30 min).
* **Layer Filters:** Planners can toggle transport modes (walking vs. cycling) and isolate specific amenity types (e.g., healthcare-only accessibility).

### Model 3: Amenity Placement Recommendation Engine
* **Function:** Decision support for municipal zoning and infrastructure investments[cite: 7].
* **Algorithm:** A population-weighted greedy heuristic / grid-search algorithm:
  * Uses German Census (**Zensus**) population density spatially distributed across the H3 hexagons.
  * Simulates placing a new amenity (e.g., clinic, supermarket, school) across candidate cells.
  * Evaluates the potential reduction in aggregate travel time, prioritizing placements that provide the largest population-weighted accessibility gain:
    $$\Delta U = \sum_{i \in \text{Hexagons}} \text{Population}_i \times \max\left(0, T_{i}^{\text{current}} - T_{i}^{\text{simulated}}\right)$$
  * Constrains candidates using OSM land-use layers to prevent placement in non-buildable zones (water, industrial, conservation areas).

## 3. Data Sources & Tooling

| Domain | Source / Library | Purpose |
| :--- | :--- | :--- |
| **Street Network & POIs** | `OSMnx`, OpenStreetMap (Overpass) | Road network graphs, pedestrian ways, bike paths, and amenity coordinates (supermarkets, schools, healthcare, parks, transit)[cite: 7]. |
| **Demographics** | Zensus (Destatis 100m grid) | Population counts transferred to H3 hexagons via areal-weighted interpolation. |
| **Routing Engine** | **Valhalla** (Dockerized) | Multimodal routing, pedestrian/cyclist costing, batch distance-matrix computation. |
| **Spatial Indexing** | **Uber H3** (`h3-py`) | Discrete global grid system for spatial aggregation and fast neighborhood lookups. |
| **Backend & Storage** | **FastAPI**, **PostgreSQL / PostGIS** | Serving precalculated grids, caching queries, running live pin inspections. |
| **Frontend** | **MapLibre GL JS**, **deck.gl** (`H3HexagonLayer`) | GPU-accelerated rendering of 10,000+ hexagons and interactive route lines. |
| **Transit (Stretch Goal)**| **R5** (`r5py`) or **OpenTripPlanner (OTP)** | Scheduled public transit integration via GTFS feeds. |
