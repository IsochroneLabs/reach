# Changelog

All notable changes to this project are documented in this file.

## [Unreleased]

- Campus sites from the university's official address list (N30): Alma buildings map to official buildings and from there to the nearest site; new sites Altstadt and Cyber Valley; Medicine, Data Science/ML, Computer science, Economics, humanities and social sciences get corrected site shares (Medicine and Data Science were wrongly sent to the Tal)
- Weekly travel time and trips per week removed from profile, results, comparison, API and data (methodology v1.5, data contract v1.4.0)
- Profile and results columns fold away, the results column can be dragged wider (three places side by side); destinations on the map show opening hours and more on hover, pinned by a click and closed with ×
- Campus and destinations on the map (N29): routes go to the student's own campus sites (with their share) instead of the nearest site of any programme; trip destinations are labelled on the map; opening hours, website and wheelchair access from OSM with "open then / closed then" for the trip window (`destination_details`, data contract v1.3.0); campus site points moved to the lecture buildings
- Application text (F4.8, building block): drafts in German and English in three tones from the student's profile, the listing and up to five personal lines kept only in `localStorage`; gaps stay visible in [brackets]
- *Find* opens on the best WGs for the profile: best fit first, the top six, the best one expanded below the list, no WG toggle; the map hides the grid while a WG is open and draws its routes, the areas are a secondary section
- Map routes and university outlines (F4.5/F4.7): a listing's fastest walk/bike trips are drawn as live Valhalla lines on the map, the map zooms to the listing and hides the other WG markers; university buildings from OSM are outlined, with the selected programme's campus sites in ink (notes N28)
- Point routing (F4.5): `POST /api/place` routes one point to the nearest k per type and label and all campus sites (Valhalla matrix for walk/bike, OpenTripPlanner per target and trip window, transit capped by walking), derives the fit from these times and caches nothing; the listing detail uses the exact point and falls back to the cell (notes N27)
- Geocoding of listing addresses moved to `pipeline/src/reach_pipeline/listings/geocode.py` (house → street → marker); the crawl uses it unchanged
- Map controls: "Kacheln" / "Grid" hides the 100 m fit grid and its legend, "WGs" shows the WG-Gesucht markers and the listing list; both choices stay in `localStorage`, so the map can show the streets and only the WG markers
- Basemap (D5): a 4.5 MB simplified extract of the Tübingen OSM roads, water, green spaces and rail (21,017 features) plus a hand-written monochrome MapLibre style, served from our own origin; the map shows streets instead of a plain background, the cells stay on top (notes N18; the N18 vector-tile build remains the production target)
- API image: `pandas` and `numpy` are declared dependencies (Juju's yes, 27 Nov 2026), so the container starts again; the DB contract test expects the listings migration
- WG-Gesucht listings in *Find* (F4.7 building block): a text toggle loads the published snapshot, photo-first cards sorted by the fit of the listing's cell, square map markers, a detail with rent, size, rooms, availability, features, the cell's trips, a link to the ad and "check this address"; `GET /api/listings` and `POST /api/listings/fit` read only `listings.listings`; 60 real Tübingen ads crawled on 27 Nov 2026 and published (notes N20, N26; F4.5 point routing still open)
- Publish robustness: empty text values (e.g. a missing postcode) stay empty strings instead of NULL, unnamed destinations get their type label, and `current` views are dropped and recreated when a run adds or reorders a column
- Listings (F4.2): parser for WG-Gesucht ad and search pages with the field spec of the data contract (contact data stripped, partial results with warnings instead of errors) and five anonymised fixtures
- Alma programme sites (F3.2–F3.4): polite crawl of the public Alma day view for one reference teaching week (`python -m reach_pipeline.alma crawl|shares`, 20 s between requests, no names stored), building → campus site and module number → programme patterns in `config/campus.yaml`, site shares per programme in `programmes.shares` and in the fit's campus time (data contract v1.2.0 draft, notes N24)
- Fit API (S1.10): `GET /api/meta`, `/destination-types` (with labels), `/label-destinations`, `/campus-sites`, `/programmes`, `/personas`; `POST /api/addresses/search`, `/api/fit` (whole city from an in-memory model of `current.travel_times`, areas with reasons, cached on run + profile), `/api/cell/{id}` (trips with bus legs and the last departure home)
- Travel times and result checks (S1.8, S1.9): stage `travel_times` (Valhalla `costmatrix` for walk and bike, OpenTripPlanner per pair for transit and bike + transit, per trip window; transit capped by walking), stage `validate_results` (V2–V8 checks, report), `publish` loads all tables of data contract v1.1.0
- Transit (S1.7): OpenTripPlanner 2.10 service in `compose.yaml` (graph build and serve), stage `transit` (GTFS clip, build config, verify route), `make refresh` builds the graph
- Destinations, addresses and address cells (S1.6): campus sites, Mensas and OSM destinations per type, address search table, address cells as origins next to populated cells, departures per stop and trip window
- Fit formula settled (S1.3, methodology v1.4-draft): s = 1 / (1 + (T / (1.25·t))⁴), worked example
- Routing targets per cell (F2.3 building block): nearest k per destination type and per offered label, deduplicated, wider candidate set for transit; config `nearest_k_label` and `transit_candidate_factor`
- Destination labels in `validate` (F2.2): supermarket brands and groups, 25 sport and 4 hobby categories and religions from OSM, same-label features within 75 m or one sports centre merged; `validate/destination_labels.parquet` and label counts with check V10 in report part 1
- Design *Atelier* for *Find* and *Check* (F1.3): fit as a large mono number, ranks and reasons as indexed lists, modes as text tags, hairline trips table, monochrome seven-step fit ramp with hatched no-data cells and a square legend
- Design *Atelier* in the web app (F1.2): tokens of `docs/design.md` (one ink, greys, hairlines, radius 0, no shadows), self-hosted Host Grotesk and IBM Plex Mono (SIL OFL 1.1, 112 KB), restyled header, profile panel, bottom sheet, toast and notices; text instead of icons in the header and mode toggles
- Profile panel (F2.5): favourite supermarkets (brands and kinds of shop, nearest of them counts) and sport/hobby categories as destinations of their own (importance and fine time, no trips per week); choice in the link (`g:` part, `sport:tennis` keys), chosen places on the map; sample data with labels
- *Check* compare (S2.6): two or three places side by side with the differences in plain language (fit, weekly travel time against rent, largest per-destination gaps), shareable link with rents only on request
- *Check* for one place (S2.5): address search or pin, fit, rank in the city, weekly travel time, trips by mode and trip window with bus details, optional listing rent kept in the browser, "better places nearby" in *Find*
- *Find* (S2.4): MapLibre map with the cell fits, legend, rank markers and a cell popup; the three best areas with reasons, weekly travel time and data date; "Check here" opens *Check*
- Profile panel (S2.3): programme hint, modes, destinations with importance, fine time and trips per week, example profiles with undo; every change recolours the results
- Web app shell (S2.2): typed API client with a fixture mode on sample data of Tübingen, English/German texts, header with Find/Check switch and address search, responsive layout with a bottom sheet on phones, student profile and places in the URL hash and `localStorage`; default campus mix `campus.default_mix` (Tal + Morgenstelle)
- Screen plan for the web app (S2.1, draft): screens for *Find* and *Check* on desktop and mobile, components, state in the URL hash and `localStorage`, fit request flow, texts EN/DE, basemap options (D5) and default campus mix proposals (`docs/app_screens.md`)
